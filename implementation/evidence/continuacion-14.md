## Defectos demostrados y corregidos

1. `Fingerprint.mtime_ns: Option<i128>` se serializaba, pero la lectura de `Command::ImportAsset` internamente etiquetado usaba un deserializador Serde que rechaza i128. Alpha.10 mostraba `JSON inválido: i128 is not supported` al autosave y después fallaba Save/reopen del guion. El usuario confirmó el mismo aviso al abrir su vídeo. El deserializador de ese campo lee i64/u64 y los amplía a i128 sin cambiar el JSON ni el tipo público. La prueba anterior falló y la posterior pasó; se verifica historia/auditoría/autosave/guardado/reapertura con mtime real. No se procesó automáticamente el medio personal de la captura.
2. Una entrega de frame antiguo después de seek pausado podía devolver el playhead a su posición previa. El resolver conserva el último destino y descarta entregas anteriores. `WaitFrame` ya compara con el destino capturado; el timeout es fallo, evitando un falso PASS del guion antiguo.
3. Exportar si aparece otro archivo en el destino durante verificación conserva sus bytes y devuelve precondición concreta. Se ejecutaron tres regresiones reales de concurrencia/cancelación/publicación exclusiva.
4. HTTP202 de notificación del puente MCP no produce respuesta stdout. Las pruebas sintéticas cubren UTF-8, errores correlacionados, exact-once y verificación diferida.
5. Windows `accept` heredaba el modo no bloqueante de la escucha. El cliente real recibía reset durante initialize y el servidor registró `WouldBlock`10035 en headers. El stream aceptado pasa explícitamente a bloqueante antes de deadlines de lectura/escritura. Prueba nativa TCP con headers/body demorados y recorrido MCP completo PASS en 14.16 s, build final SHA `8ba5193593d6d7eaf406169bf88158af3ecdbf98a6d4fc5f25cc9ac9c4aabd26`. Evidencia y primeros fallos conservados en el informe E4.
6. El hook Save del guion sustituía el store incluso al guardar sobre el mismo proyecto y perdía la base; Save As además perdía el store fuente para copiar auditoría. El helper común conserva el origen hasta completar el guardado y reutiliza el store actual al guardar en la misma ruta. Guion MCP final guarda/reabre revision5 correctamente.

Ctrl+N crea una capa manual vacía. El usuario observó esa capa y confirmó que pudo añadir un tramo; esa observación acredita esa interacción en alpha.10, sin aceptar audio, foco o guardado corregido. La ventana antigua se conservó hasta que el usuario confirmó cierre, para evitar perder trabajo. El primer build nuevo falló por bloqueo del exe abierto (`Access denied`, OS5); el fallo se conserva en [build inicial](build-continuacion-14-initial.log).

## E5: frontera Rust/Python

`tv2-pipeline` toma snapshot de proyecto/revisión/digest/asset y SHA completo de fuente/modelo/worker. Persiste jobs y leases, valida protocolo/eventos, acota stdout/stderr, cancela con gracia y recoge procesos. Windows Job Object kill-on-close limita los descendientes al proceso propio; no se promete esa garantía en otras plataformas con el fallback actual. Python devuelve artefactos declarados y nunca escribe el proyecto.

La preparación exige correspondencia de identidad, fuente, modelo, revisión y digests, rechaza rutas escapadas/symlinks y verifica exactamente los bytes leídos. No importa siblings del folder de resultados. La incorporación es un comando común preparado de actor External, explícito en GUI, con protecciones humanas/tombstones, preview e idempotencia. La revisión de un resultado contra una revisión nueva exige acción local explícita; no se rebindea silenciosamente el recibo del worker. Save As conserva master, bundle, historia y receipt cuando desaparece la carpeta original. [Contratos finales](e5-pipeline-contracts-final.log): 12 PASS; el [primer fallo](e5-pipeline-contracts.log) era una fixture que no resolvía `@project` después de Save As.

Extracción y transcripción tienen claves separadas. Cambiar modelo/idioma/job/revisión reutiliza solo extracción por contenido/hash y cambia la clave ASR. La prueba independiente usa metadata de otro modelo para comprobar claves; no acredita ejecutar ese modelo. Intensidad y heurísticas se derivan ahora después del transcript, con checkpoint propio y transcript raw inmutable. Los 14 tests usan PCM y palabras inventadas; el ejemplo Rust demuestra parser/proyecciones/preparación/commit/undo en memoria de ese payload y declara explícitamente que no hubo ASR ni GUI.

MMS usa otro runtime `.local/e5-alignment-venv`, lock exacto Torch/Torchaudio2.8.0+cpu y Python3.12.13. Primera carga nativa PASS, distinta de PyAV bloqueado. El wheel Torch descargó 590.7 MiB frente a la estimación inicial de240 MB; modelo MMS_FA 1262047414 bytes descargado desde URL pública a `.local/models/mms-fa/model.pt`, SHA256 `20ef12963ab4924bef49ac4fc7f58ad5da2ee43b2c11bc8c853c9b90ecdbc680`, CC-BY-NC4. El digest es medición local, no firma upstream. Manifest y provenance preservados; no se redistribuyen pesos ni se declara inferencia por la descarga. Worker standalone en implementación; integración de esta etapa/DAG en Rust/GUI pendiente.
